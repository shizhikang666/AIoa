# Problem Optimization Log

Purpose: keep a living table of problems found during the ThinkPHP OA refactor, the practical mitigation already applied, and the next optimization to make future work faster and safer.

Update this file whenever a new recurring problem, blocker, confusing workflow, slow command, avoidable mistake, or test gap appears. Do not record secrets, local credentials, tokens, raw `.env` values, or production data.

## Update Rules

- Add a row for each meaningful problem encountered during project work.
- Keep the row concise: what happened, why it matters, root cause, mitigation, and next improvement.
- Revisit existing rows before adding duplicates; update the existing row if the same problem reappears.
- Prefer concrete commands, docs, or scripts that prevent recurrence.
- Mark status as `Open`, `Mitigated`, or `Closed`.

## Review Checklist

Before starting a new implementation slice:

1. Run `.\scripts\project-progress.ps1 -Lean`.
2. Scan this table for `Open` problems related to the slice.
3. Update an existing row if the same problem repeats.
4. Add a new row if the problem is new and likely to recur.
5. Mention important new or changed problem rows in `STATUS.md` for the completed slice.
