# Manual Test Issues

Date started: 2026-06-15

This file tracks issues found during manual browser testing of the ThinkPHP OA migration. Add items here when a problem appears to be a product, frontend/backend compatibility, data-shape, or unfinished-route issue. Environment-only problems, such as a stopped local dev server, should be fixed directly and recorded only when they repeatedly block testing.

## Notes

- Likely impact: users cannot confidently choose the intended parent organization when creating or editing organizations.
- Suggested first check: compare the `/sys/org/orgTreeSelector` response fields with the Ant Design Vue tree-select field mapping used by `snowy-admin-web/src/views/sys/org/form.vue`.
- MT-002 regression check: `RoleService` `page`/`detail`/`add`/`edit` return rows must keep the copied Vue role shape `id/name/category/sortCode/orgId`; run `scripts/online-role-crud-grant-smoke.ps1` (`Assert-RoleRowShape`) after any change to `RoleService::roleRow()` or role controllers.
- MT-003 regression check: invalid login should return `code=401` with Chinese `message/msg`, for example `账号或密码错误`.
- MT-004 regression check: tenant IDs on the login page must remain strings end to end; do not use `parseInt` or numeric coercion for 20-digit IDs.
- MT-005 regression check: login endpoint `401` should show the backend login message, not the global relogin modal.
- MT-006 regression check: when captcha is disabled, login payload must not include `validCode`/`validCodeReqNo`; stale captcha fields should not block login server-side.
- MT-007 regression check: accounts with no authorized menus should receive a clear frontend permission message; accounts intended for testing must be granted a role/resource set before login smoke expects navigation.
- MT-008 regression check: `/sys/user/grantResource` must return a specific Chinese `message/msg`; assigning system-module resources to a non-super-admin target user should return `只有超管角色用户可以授权系统模块资源`, not generic `请求失败`.
