## Engine Tables

The Java project uses Camunda-style `act_*` tables.

| Table | Purpose | Important Columns | Notes |
| --- | --- | --- | --- |
| `act_re_procdef` | Process definitions | `ID_`, `KEY_`, `NAME_`, `VERSION_`, `DEPLOYMENT_ID_`, `RESOURCE_NAME_`, `STARTABLE_` | Contains deployed BPMN definitions such as `Process_ask_leave`, `Process_reimbursement` |
| `act_re_deployment` | Deployment records | `ID_`, `NAME_`, `DEPLOY_TIME_`, `SOURCE_`, `TENANT_ID_` | Links process definitions to deployment metadata |
| `act_ge_bytearray` | BPMN resource bytes | `ID_`, `NAME_`, `DEPLOYMENT_ID_`, `BYTES_` | Stores BPMN XML and other binary resources |
| `act_ru_execution` | Runtime execution/process tree | `ID_`, `PROC_INST_ID_`, `PROC_DEF_ID_`, `ACT_ID_`, `IS_ACTIVE_`, `TENANT_ID_` | Runtime state for active process instances |
| `act_ru_task` | Runtime user tasks | `ID_`, `PROC_INST_ID_`, `PROC_DEF_ID_`, `TASK_DEF_KEY_`, `ASSIGNEE_`, `CREATE_TIME_` | Pending task list is filtered by `ASSIGNEE_` |
| `act_ru_variable` | Runtime variables | `ID_`, `PROC_INST_ID_`, `TASK_ID_`, `NAME_`, `TYPE_`, `TEXT_`, `LONG_`, `DOUBLE_`, `BYTEARRAY_ID_` | Holds `title`, `status`, `amount`, `org`, `tenantId`, approver lists, etc. |
| `act_hi_procinst` | Historic process instances | `ID_`, `PROC_INST_ID_`, `PROC_DEF_KEY_`, `PROC_DEF_ID_`, `START_TIME_`, `END_TIME_`, `START_USER_ID_`, `STATE_` | Used for process pages/detail |
| `act_hi_taskinst` | Historic task instances | `ID_`, `TASK_DEF_KEY_`, `PROC_DEF_KEY_`, `PROC_INST_ID_`, `ASSIGNEE_`, `START_TIME_`, `END_TIME_` | Used for history task page |
| `act_hi_varinst` | Historic variables | `ID_`, `PROC_INST_ID_`, `TASK_ID_`, `NAME_`, `VAR_TYPE_`, `TEXT_`, `LONG_`, `DOUBLE_`, `STATE_` | Used for process detail, list labels, and search filters |
| `act_hi_actinst` | Historic activities | `ID_`, `PROC_DEF_KEY_`, `PROC_INST_ID_`, `ACT_ID_`, `ACT_NAME_`, `ACT_TYPE_`, `ASSIGNEE_`, `START_TIME_`, `END_TIME_` | Useful for timeline/review history |
| `act_hi_comment` | Comments | `ID_`, `TASK_ID_`, `PROC_INST_ID_`, `USER_ID_`, `MESSAGE_`, `TIME_` | Not yet traced in Java service implementation, but can support approval opinions |
| `act_ru_identitylink` / `act_hi_identitylink` | Identity links | `TASK_ID_`, `PROC_INST_ID_`, `USER_ID_`, `GROUP_ID_`, `TYPE_` | May be needed if candidate users/groups are introduced |

## Index Notes

Existing `act_*` tables already include useful indexes:

- `act_ru_task`: `ASSIGNEE_`, `CREATE_TIME_`, `PROC_INST_ID_`, `PROC_DEF_ID_`
- `act_ru_variable`: `PROC_INST_ID_`, `TASK_ID_`, `NAME_`, `VAR_SCOPE_ + NAME_`
- `act_hi_procinst`: `PROC_DEF_KEY_`, `START_TIME_ + END_TIME_`, `END_TIME_`
- `act_hi_taskinst`: `ASSIGNEE_`, `PROC_INST_ID_`, `PROC_DEF_KEY_`, `START_TIME_`, `END_TIME_`
- `act_hi_varinst`: `PROC_INST_ID_ + NAME_ + VAR_TYPE_`, `NAME_`

No new index is proposed in this phase because workflow-agent is not modifying database schema.

## ThinkPHP Model Guidance For Later

Later model naming should avoid colliding with db-agent decisions. Suggested read-oriented model names:

- `ActReProcdef`
- `ActRuExecution`
- `ActRuTask`
- `ActRuVariable`
- `ActHiProcinst`
- `ActHiTaskinst`
- `ActHiVarinst`
- `BizCcRecord`
- `SysUserProcessConfig`

Do not create these models in Phase 1. Coordinate with db-agent before implementation.
