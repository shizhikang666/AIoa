# Java OA 到 ThinkPHP 总体重构路线

## 总原则

- 原 Java 项目只读分析，不直接修改。
- ThinkPHP 项目先建立工程规范，再按模块迁移。
- 每个阶段先形成文档和接口契约，再实现代码。
- 避免一次性大迁移，优先按模块、按接口、按测试闭环推进。

## 第一阶段：项目分析

- 梳理 Java 多模块结构、启动入口、配置方式。
- 分析 Controller、Service、Mapper、Entity、VO/DTO 分层。
- 记录核心业务模块和模块依赖。
- 输出 Java 模块清单、接口清单和风险点。

## 第二阶段：数据库映射

- 汇总 Java 项目 SQL、实体类、Mapper 查询。
- 建立 MySQL 表结构、字段类型、索引和关系说明。
- 设计 ThinkPHP Model 命名、字段映射和软删除约定。
- 明确迁移脚本和初始化数据策略。

## 第三阶段：权限认证

- 分析登录、Token、Redis 会话、权限拦截逻辑。
- 设计 ThinkPHP Token + Redis 认证中间件。
- 梳理 RBAC：用户、角色、菜单、按钮、接口权限。
- 输出权限接口契约和前端菜单数据结构。

## 第四阶段：用户组织

- 迁移用户、部门、岗位、组织架构。
- 明确用户和组织的树结构、排序、状态、租户字段。
- 梳理用户扩展信息和组织权限边界。
- 建立用户组织相关接口映射。

## 第五阶段：工作流

- 分析审批流定义、流程实例、审批记录、抄送记录。
- 明确 Java 工作流依赖和 ThinkPHP 可替代实现。
- 先输出流程数据模型和状态机设计。
- 再分阶段迁移请假、报销、付款等流程。

## 第六阶段：API 重构

- 按 Java Controller 映射 ThinkPHP Controller。
- 保持接口路径、参数和返回格式尽量兼容。
- 对不可兼容点输出变更说明。
- 建立统一异常处理、参数验证和分页格式。

## 第七阶段：前端适配

- 统计前端调用的 API、Token 处理、菜单渲染、权限按钮。
- 适配 ThinkPHP 返回格式和错误码。
- 保持页面功能不变，避免重写 UI。
- 输出前端接口变更表。

## 第八阶段：测试与修复

- 建立 PHP 语法检查、路由检查、接口冒烟测试。
- 对比 Java 旧接口和 ThinkPHP 新接口行为。
- 补充权限、菜单、用户、流程的关键用例。
- 修复兼容性和数据边界问题。

## 第九阶段：部署上线

- 确认 PHP、Composer、Redis、MySQL、Web Server 版本。
- 编写环境变量、目录权限、缓存、日志配置说明。
- 制定灰度切换和回滚方案。
- 输出部署手册和上线检查清单。
